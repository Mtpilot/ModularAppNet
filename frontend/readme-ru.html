Modular Monolith Template (перевод README)

Описание проекта

Этот проект — современный, хорошо структурированный шаблон для построения поддерживаемых модульных монолитных приложений на .NET. Он демонстрирует, как организовать код в отдельные модули, которые слабо связаны между собой, но развёртываются как одно приложение.

Шаблон показывает корректное моделирование домена, чистое разделение ответственности и продуманный подход к межмодульному взаимодействию — без излишнего усложнения. Подробное введение см. в статье Building a Modular Monolith with Vertical Slice Architecture in .NET .

Модули

Приложение состоит из 4 основных модулей:

  • Users Module: аутентификация и авторизация пользователей с использованием JWT-токенов.
  • Shipments Module: управление полным жизненным циклом отправлений от создания до доставки.
  • Carriers Module: управление перевозчиками (службами доставки).
  • Stocks Module: учёт товарных запасов и доступности.

Common Packages: общие библиотеки, утилиты и интерфейсы, используемые во всех модулях.

Взаимодействие модулей

  • Shipments Module обращается к модулям Carriers и Stocks для проверки существования перевозчиков и доступности товаров.
  • Поток аутентификации: модули Shipments, Carriers и Stocks требуют аутентифицированного пользователя, но не вызывают напрямую Users-модуль. Пользователь получает JWT и refresh-токен из Users-модуля и использует их для авторизации запросов в другие модули.

Подробнее об этом: How to Implement Refresh Tokens and Token Revocation in ASP.NET Core и Authentication and Authorization Best Practices in ASP.NET Core .

NuGet-пакеты

  • FluentValidation: удобное построение типобезопасных правил валидации.
  • Entity Framework Core: ORM для доступа к базе данных с чистым разделением уровня хранения.
  • ASP.NET Core: веб-фреймворк для REST API (используются Minimal APIs).
  • OpenTelemetry: метрики, логи и трейсы для наблюдаемости.
  • Swagger/OpenAPI: генерация документации API с интерактивным UI.

Docker-окружение

Проект использует Docker Compose для запуска всех необходимых сервисов:

  • shipping-modular-monolith: основной контейнер приложения (./ModularMonolith.Host/Dockerfile).
  • postgres: база PostgreSQL для всех модулей.
  • seq: платформа структурированного логирования.
  • jaeger: система распределённой трассировки.

Запуск

  1. Установить Docker и Docker Compose.
  2. Перейти в корень проекта.
  3. Выполнить docker-compose up -d.
  4. Открыть Swagger по адресу http://localhost:5000/swagger.
  5. Открыть Seq по адресу http://localhost:8081.
  6. Открыть Jaeger по адресу http://localhost:16686.

Структура проекта

  • /src/ModularMonolith.Host: точка входа приложения, конфигурация и запуск модулей.
  • /src/Common: общие абстракции, расширения и утилиты.
  • /src/Users: аутентификация и управление пользователями.
  • /src/Carriers: управление перевозчиками.
  • /src/Stocks: управление запасами.
  • /src/Shipments: обработка и отслеживание отправлений.

Основные API-эндпоинты

Users Module

  • POST /api/users/register — регистрация пользователя.
  • POST /api/users/login — логин и получение JWT.

Carriers Module

  • POST /api/carriers — создать перевозчика.
  • GET /api/carriers/{name} — получить перевозчика по имени.

Stocks Module

  • POST /api/stocks — создать запись о запасе.
  • GET /api/stocks/{productName} — получить запас по имени товара.

Shipments Module

  • POST /api/shipments — создать отправление.
  • GET /api/shipments/{number} — получить отправление по номеру.
  • POST /api/shipments/process/{number} — перевести в статус processing.
  • POST /api/shipments/dispatch/{number} — статус dispatched.
  • POST /api/shipments/transit/{number} — статус in-transit.
  • POST /api/shipments/deliver/{number} — статус delivered.
  • POST /api/shipments/receive/{number} — статус received.
  • POST /api/shipments/cancel/{number} — отмена отправления.

Тесты

В проекте есть как модульные, так и интеграционные тесты:

  • Юнит-тесты: доменные правила, обработчики use case, валидация и т.п.
  • Интеграционные тесты: полный путь от HTTP-запроса до базы данных, проверка happy-path и ошибок.

Архитектура

Проект комбинирует Vertical Slice Architecture и Clean Architecture:

  • Vertical Slices: фичи организованы по бизнес-функциональности, а не по слоям.
  • Clean Architecture: доменная модель изолирована от инфраструктуры.

Основные решения:

  • Ручные хендлеры вместо MediatR для упрощения.
  • Прямое использование EF Core без дополнительных Repository/Unit of Work абстракций.
  • Явное маппирование DTO ↔ доменные объекты.
  • Result-паттерн вместо исключений для ошибок бизнес-логики.

Наблюдаемость

  • OpenTelemetry — метрики, логи и трассировка.
  • Seq — централизованное структурированное логирование.
  • Jaeger — визуализация распределённых трассировок.

Конфигурация для разработки

  • .editorconfig — единый стиль кода.
  • Directory.Build.props — общие настройки сборки, анализаторы, правила стиля.
  • Directory.Packages.props — централизованное управление версиями пакетов.
